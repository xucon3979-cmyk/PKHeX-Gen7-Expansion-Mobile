# v0.8.0 — Gen7 save corruption hotfix

**Critical regression in v0.7.0: do not use v0.7.0 to export Ultra Sun/Ultra Moon saves.**

## Confirmed code-level root cause

The v0.7.0 Safe Save checker passed the **same mutable byte[] scheduled for export** to `SaveUtil.GetSaveFile(bytes)` and, if necessary, `new SAV7USUM(bytes)`.

PKHeX.Core's `SAV7USUM(Memory<byte>)` constructor calls `ClearMemeCrypto()`, which clears 0x80 bytes at `0x6C100` in its backing buffer. Both parser paths can therefore erase the export's Gen7 MemeCrypto signature before `FileSaver.SaveAsync` writes it. Checksums may still look valid while the game rejects the save.

The import path had an analogous bug: it backed up the byte[] *after* parsing, so the supposed "imported original" app-private backup could also lack the original signature.

## v0.8.0 changes

- **Export:** check MemeCrypto RSA signature + SHA256 checksum-table hash before any parsing; validate by parsing an **independent clone**; recheck the original, signed export buffer.
- **Import:** pass an **independent clone** of the raw file bytes to FileUtil, preserving the exact imported bytes for private backup.
- **Save test:** synthetic USUM write/read regression test now verifies that inspection leaves the signed output intact, including the 0x80 signature and SHA256 of the 0x150-byte checksum table. Includes the expansion Mega Greninja form plus Shiny Charm (item 632, 1× Key Items).
- **Inventory guard:** refuse out-of-range item IDs, wrong pockets, invalid quantities, duplicate entries and pouch overflow in USUM. Disable bulk Give All and Modify All actions for USUM until their risk can be evaluated.
- Preserves the original PKHeX.MAUI UI, original sprites, existing PKHaX toggle, and v0.7 on-device backups.

## User-supplied save privacy and validation limit

A user supplied a **working USUM `main` file** (445,440 bytes) in the private ChatGPT conversation. **It has not been committed to the public repository or included in CI.** Current GitHub Actions tests use a deliberately synthetic save and check Android emulator startup; a successful workflow does **not** prove that arbitrary player saves work without corruption.

To identify any remaining game-specific issue, collect both (a) the exact known-good original `main` and (b) the exact, *bad exported* `main` file created by the editor. Check both offline/private, including CRC block metadata, RSA signature, size, and data differences. Never distribute saves with trainer/private data publicly.

## Installation advice

Keep the known-good original `main` backed up OUTSIDE Android private app storage. Don't try to repair the corrupt export by copying it over the healthy one. Use a test copy for a first **no-change export** before experimenting with adding Pokémon, Shiny Charm or expansion forms. The experimental changes must be verified in the actual game or emulator.

**APK signing:** the CI workflow supports stable signing via repository secrets but defaults to ephemeral debug keys; consequently installation over v0.7 may fail until a persistent signing key is configured.
